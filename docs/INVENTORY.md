# Component inventory and extraction decisions

The analysis precedes implementation. Source evidence and snapshot IDs are in [BulkPixel](analysis-bulkpixel.md), [PineFetch/RSS](analysis-pinefetch-rss.md) and [Billly/website](analysis-billly-website.md). A pattern is shared when it is useful in at least two consumers; no consumer's full stylesheet, layout or data logic is imported.

| Shared contract                                                                  | Observed overlap / purpose                                                                                                      | Implementation boundary                                                         |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Tokens, type, focus, motion, spacing                                             | All consumers need a consistent family; BulkPixel supplies calm dark neutrals, website supplies the existing Comfortaa identity | Local fonts, opt-in base/prose, no body overflow or user-select lock            |
| Button, icon button, links                                                       | Every consumer has main, secondary and destructive actions                                                                      | Semantic variants/native states, no action handlers                             |
| Field, input types, select, textarea, checkbox/radio, switch, range, input group | BulkPixel settings; PineFetch settings; RSS topics/rules; Billly forms; website search                                          | Real labels and native controls; no validation engine or settings persistence   |
| Segmented choice                                                                 | BulkPixel format/size, PineFetch/RSS view/filter choices, Billly categories                                                     | Native mutually exclusive radios; separate from tabs                            |
| Tabs                                                                             | PineFetch detail panels, Billly views, RSS settings                                                                             | ARIA associations, roving focus, keys; no routing/data loading                  |
| Panel/section/container/stack/inline/cluster/grid/split/toolbar                  | Tool settings and content grouping across consumers                                                                             | Lightweight responsive primitives, no fixed app workspace                       |
| Menu/dropdown/tooltip/dialog/toast                                               | BulkPixel preset menu and dialogs; PineFetch native dialog/tabs; RSS menus/custom modal/toast                                   | Safe text, escape/outside/focus behavior; no API/undo/file operations           |
| Table/compact/numeric/sort/selected/sticky                                       | Billly invoices/customers, website article/project tables                                                                       | Semantic HTML and presentation; sorting and row actions remain app code         |
| List/interactive/key-value/definition                                            | PineFetch history/details, RSS settings/feed, Billly detail, website feature lists                                              | Native links/buttons and definition semantics; no item data model               |
| Badge/tag/status/alert/inline feedback                                           | All tools and article metadata                                                                                                  | Semantic status independent of accent; text labels, no color-only information   |
| Metric/metric card                                                               | BulkPixel statistics, PineFetch counts, Billly dashboard                                                                        | Label/value composition, no chart/aggregation library                           |
| Progress/spinner/skeleton/empty                                                  | Conversion/download queues, RSS loading, Billly processing                                                                      | Native progress and readable loading/empty copy; no queue state                 |
| Dropzone/path/code                                                               | BulkPixel import/output, PineFetch paths/logs, website CLI/code                                                                 | Dropzone presentation/native button; file handling left to app                  |
| Prose/article card/project card/meta/byline/callout/blockquote                   | RSS article cards, website blog/project pages                                                                                   | Opt-in 68ch reading context and generic content surfaces                        |
| Top/sidebar navigation/breadcrumb/pagination/site header/footer                  | Tool navigation, RSS sidebar, website archive/header/footer                                                                     | Native nav/links, current-page semantics, wrapping; no router/menu destinations |
| Accordion                                                                        | Settings disclosure and RSS export `details` establish disclosure need                                                          | Native `details` with styled `summary`; no JS recreation                        |

Context menus are not included in 0.1: the shared action menu covers the audited cross-consumer need; pointer-coordinate context actions can be added after a specific reusable contract is established.

## Differences deliberately preserved

Product accent/branding, information architecture and content stay local. BulkPixel owns previews, metadata inspector, conversion workspace and watched-folder logic. PineFetch owns queue/history/media/download/transcription integration. RSS owns triage, topics, digests, feeds and embedded article view. Billly owns invoice/customer/billing workflows and chart data. The website owns templates, navigation hierarchy, taxonomy, search index, SEO and page composition.

## Corrections from source evidence

PineFetch and RSS use history/feed lists, not native tables in the inspected snapshots. Billly is available locally but the requested public `Billly` URL is unavailable; its remote is `Billy`. The deployed website currently uses red `#FF4A4A`; purple is the new requested theme preset. Its current build uses Eleventy despite older Jekyll template ancestry; static Jekyll integration is still documented for future consumers.
