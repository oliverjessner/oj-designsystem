# JavaScript API

ESM, no automatic DOM work and no UI framework dependencies. Importing on a server is safe. DOM-creating helpers require a real browser root; initialize after markup is mounted. Browser support is current Chrome, Safari, Firefox and Edge, including native `<dialog>`. No experimental Popover API or polyfill is required.

```js
import {
  initOJ,
  initTabs,
  initDropdowns,
  initTooltips,
  initDialogs,
  initCountUps,
  initVideoPreviews,
  openDialog,
  closeDialog,
  confirmDialog,
  toast,
} from 'oj-designsystem';
const cleanup = initOJ(document.querySelector('#workspace'));
// Before disposal:
cleanup();
```

All initializers accept an optional Document/Element root, include the root itself if it matches, return a cleanup function, and use component ownership to avoid duplicate listeners. Calling initialization again discovers new nodes. **Only the call that first initialized a component owns its cleanup**; a later no-op initialization cannot destroy earlier components. Cleanup restores original tab/menu attributes and visibility, removes generated tooltips, closes managed native dialogs, and permits reinitialization. Dialog cleanup closes a managed dialog even if it was already open when initialized. Keep the original cleanup handle for each mounted scope. Nested tabs/menus are isolated. Initialization does not observe DOM mutations automatically.

## Tabs

`data-oj-tabs` contains `role="tablist"` with a label, button `role="tab"` children and `role="tabpanel"` content. Provide stable `id` / `aria-controls` / `aria-labelledby` where possible; missing associations are generated by order. Exactly one enabled tab is selected. Automatic activation: horizontal arrows (including RTL), Home/End; vertical lists (`aria-orientation="vertical"`) use Up/Down. Disabled/aria-disabled tabs are skipped. Content panels receive a tab stop unless the consumer already defines one. Panels remain readable without JS; initialization hides inactive panels. Use native radios for segmented data choices, not tabs.

`oj:change` bubbles from the tab container: `{ tab, panel, index }`.

## Dropdown/action menu

```html
<div class="oj-dropdown" data-oj-dropdown>
  <button class="oj-button oj-button-secondary" data-oj-dropdown-trigger>
    Actions
  </button>
  <div
    class="oj-menu"
    data-oj-dropdown-menu
    role="menu"
    aria-label="Actions"
    hidden
  >
    <button class="oj-menu-item" role="menuitem" data-oj-value="duplicate">
      Duplicate
    </button>
  </div>
</div>
```

Click or Enter/Space opens. Down/Up on the trigger opens at first/last enabled item; menu Up/Down/Home/End moves focus, character typing searches items. Escape closes and returns focus; outside click closes without stealing focus; Tab closes while preserving natural navigation. Item click emits `oj:select` with `{ item, value }`; `preventDefault()` keeps the menu open. Consumers manage checkbox/radio menu state and execute actions. `oj:open`/`oj:close`: `{ trigger, menu }`. For ordinary site navigation use native links, not menu roles.

## Tooltip

Set `data-oj-tooltip="Settings"` on an accessible trigger. `initTooltips` provides a plain-text `role="tooltip"` description on focus/hover, preserves existing `aria-describedby`, positions within the viewport and supports hover over the tooltip plus Escape dismissal. The tooltip is mounted in the owner document body (or its native dialog), hidden on dismissal and removed on cleanup. Essential instructions belong in visible text, never solely in a tooltip. Icon-only triggers still need `aria-label`.

`oj:open`/`oj:close` bubble from trigger with `{ trigger, tooltip }`.

## Native dialogs

Give `dialog.oj-dialog[data-oj-dialog]` a title via `aria-labelledby`. Declarative open buttons use `data-oj-dialog-open="id"`; close buttons inside use `data-oj-dialog-close` or a return-value string. Native `method="dialog"` forms work too.

```js
openDialog('settings', { root: document, trigger: settingsButton });
closeDialog('settings', 'saved');
const confirmed = await confirmDialog({
  title: 'Delete project?',
  message: 'This action cannot be undone.',
  confirmLabel: 'Delete',
  cancelLabel: 'Cancel',
  variant: 'danger',
});
```

The browser handles modal focus/inertness/Escape. Helpers preserve an opener and restore focus if it remains connected; autofocus is honored. `confirmDialog` inserts safe text, focuses Cancel, resolves false for cancellation/Escape, and removes temporary markup/listeners. `oj:open`/`oj:close` bubble from dialog: `{ dialog, returnValue }`. Do not nest native dialogs in other dialogs or provide an inert root.

## Video previews

`initVideoPreviews(root?)` discovers cards with `data-oj-video-preview`, including the root itself. It is included in `initOJ` and supports element, document and shadow-root scopes. A card needs its own `video.oj-video-card-media` and enabled native `button[data-oj-video-toggle]`; nested cards own their own controls. Incomplete markup or missing `IntersectionObserver` is left untouched.

```html
<article
  class="oj-card oj-video-card"
  data-oj-video-preview
  data-oj-video-play-label="Vorschau abspielen"
  data-oj-video-pause-label="Vorschau pausieren"
>
  <video
    class="oj-video-card-media"
    controls
    playsinline
    preload="metadata"
    aria-label="Research introduction"
  >
    <source src="/assets/introduction.mp4" type="video/mp4" />
  </video>
  <div class="oj-card-body">
    <h3 class="oj-card-title">Research introduction</h3>
    <div class="oj-card-actions">
      <button
        type="button"
        class="oj-button oj-button-secondary"
        data-oj-video-toggle
        hidden
      >
        Vorschau abspielen
      </button>
    </div>
  </div>
</article>
```

Initialization disables native autoplay, sets muted/loop/inline playback and reveals the authored button. Playback starts at 35% viewport intersection and pauses offscreen or in a hidden document. Reduced motion prevents automatic playback and stops an automatic preview immediately when enabled; explicit manual playback remains available. Omitting the initializer keeps native video controls as the no-JavaScript fallback. Do not author `autoplay` on preview media.

The native button supports Enter/Space and never changes focus. It displays `Play preview` / `Pause preview`, or the literal localized `data-oj-video-play-label` / `data-oj-video-pause-label`. It uses `aria-controls` for the video; a missing video ID is generated. Pausing through the button or native media controls switches to manual control so scrolling back does not restart playback. Rejected autoplay or a media error pauses the preview and leaves the manual control available; promise rejections do not escape into the consumer.

Runtime `data-oj-video-state` is `paused`, `loading`, `playing` or `blocked`. The initializer emits no custom events; use native media events when needed. Only the original initializer owns cleanup. Cleanup disconnects observers/listeners, cancels queued starts, pauses media, restores authored media settings, button contents/visibility, IDs/associations and card state. It leaves playback position alone and permits reinitialization. New cards are discovered by a later call, with no automatic DOM mutation observation.

## Count-up animation

`initCountUps(root?)` discovers text-only elements with `data-oj-count-up`, including the root itself. `initOJ(root?)` includes this initializer. It also works with a shadow-root scope. Initialization is explicit and importing the module never accesses browser globals.

```html
<span
  data-oj-count-up="1000"
  data-oj-count-locale="de-DE"
  data-oj-count-suffix="h"
  >1.000h</span
>
```

Always render the complete final value in the HTML. The target attribute contains an ungrouped decimal number with a period as decimal separator, such as `1000`, `99.9` or `-12.5`. It is separate from localized display text. The final text is restored exactly after animation. Use matching HTML and formatting attributes to keep the number width stable.

| Attribute                | Meaning / default                                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `data-oj-count-up`       | Required finite numeric target; absolute value must not exceed `Number.MAX_SAFE_INTEGER`. Zero and negative values are supported.                |
| `data-oj-count-locale`   | `Intl.NumberFormat` locale; defaults to the closest `lang`, then document language, then browser locale.                                         |
| `data-oj-count-decimals` | Integer from 0 to 20; defaults to the target's fractional precision, capped at 20.                                                               |
| `data-oj-count-prefix`   | Literal text before the animated number, such as `€`; default empty.                                                                             |
| `data-oj-count-suffix`   | Literal text after the animated number, such as `h` or `%`; default empty.                                                                       |
| `data-oj-count-duration` | Positive finite duration in milliseconds; default 1800. Invalid values use the default.                                                          |
| `data-oj-count-delay`    | Nonnegative finite delay in milliseconds after visibility; default 0. Use 0/90/180 for a staggered row.                                          |
| `data-oj-count-state`    | Runtime-owned `pending`, `running` or `complete`; original attribute restored on cleanup. No runtime state is added when enhancement is skipped. |

The number animates from zero with cubic ease-out once at least 65% of it is visible. It does not restart after scrolling away/back or a repeated initialization. Cleanup releases that call's observers, animation frames and media listeners, restores original text nodes/classes/state and permits a fresh animation. New nodes are discovered by a later initializer call; DOM mutations are not observed automatically.

Without JavaScript, `IntersectionObserver` or animation-frame support, or when reduced motion is already requested, the authored final text stays visible. If reduced motion is enabled while waiting/animating, the animation stops immediately at the final value and does not restart if the preference changes back. Detached running elements also finish without scheduling further frames.

During animation the final value remains available as screen-reader text. The animated text and invisible width reserve are `aria-hidden`; intermediate counts create no live announcements or tab stops. Generated helper classes are `oj-count-up`, `oj-count-up-current` and `oj-count-up-reserve`. User strings use `textContent`. Invalid targets, precision or locales and elements with child markup retain their authored content. There are no custom events or replay controls in the library; dispose/reinitialize the owned scope for an explicit replay, as shown in Storybook.

## Toast

```js
const notification = toast('Export completed', {
  type: 'success',
  duration: 4000,
  root: document,
  dismissLabel: 'Dismiss notification',
});
notification.dismiss();
```

Types: info (default), success, warning, danger; error aliases danger. Duration is milliseconds; 0 persists until dismissed. Toasts stack in a local region, have live announcements and labeled dismiss controls, and pause timers while hovered/focused. Root defaults to the document; a theme-scoped element root preserves the local product identity. The region is removed after its final toast is dismissed. Avoid auto-dismissing essential information; use persistent alerts or duration 0 when user action is required.

Returns `{ element, dismiss }`. `oj:open`/`oj:close` bubble with `{ element, type }`. Message values are rendered with `textContent`; there is no HTML message mode, remote script loading or business state. Other helpers also treat text literally.
