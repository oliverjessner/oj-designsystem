# JavaScript API

ESM, no automatic DOM work and no UI framework dependencies. Importing on a server is safe. DOM-creating helpers require a real browser root; initialize after markup is mounted. Browser support is current Chrome, Safari, Firefox and Edge, including native `<dialog>`. No experimental Popover API or polyfill is required.

```js
import {
  initOJ,
  initTabs,
  initDropdowns,
  initTooltips,
  initDialogs,
  openDialog,
  closeDialog,
  confirmDialog,
  toast,
} from 'oj-designsystem';
const cleanup = initOJ(document.querySelector('#workspace'));
// Before disposal:
cleanup();
```

All initializers accept an optional Document/Element root, include the root itself if it matches, return a cleanup function, and use component ownership to avoid duplicate listeners. Calling initialization again discovers new nodes. **Only the call that first initialized a component owns its cleanup**; a later no-op initialization cannot destroy earlier components. Cleanup restores original tab/menu attributes and visibility, removes generated tooltips, closes managed native dialogs, and permits reinitialization. Dialog cleanup closes a managed dialog even if it was already open when initialized. Keep the original cleanup handle for each mounted scope. Nested tabs/menus are isolated. Initialization does not observe DOM mutations automatically.

## Tabs

`data-oj-tabs` contains `role="tablist"` with a label, button `role="tab"` children and `role="tabpanel"` content. Provide stable `id` / `aria-controls` / `aria-labelledby` where possible; missing associations are generated by order. Exactly one enabled tab is selected. Automatic activation: horizontal arrows (including RTL), Home/End; vertical lists (`aria-orientation="vertical"`) use Up/Down. Disabled/aria-disabled tabs are skipped. Content panels receive a tab stop unless the consumer already defines one. Panels remain readable without JS; initialization hides inactive panels. Use native radios for segmented data choices, not tabs.

`oj:change` bubbles from the tab container: `{ tab, panel, index }`.

## Dropdown/action menu

```html
<div class="oj-dropdown" data-oj-dropdown>
  <button class="oj-button oj-button-secondary" data-oj-dropdown-trigger>
    Actions
  </button>
  <div
    class="oj-menu"
    data-oj-dropdown-menu
    role="menu"
    aria-label="Actions"
    hidden
  >
    <button class="oj-menu-item" role="menuitem" data-oj-value="duplicate">
      Duplicate
    </button>
  </div>
</div>
```

Click or Enter/Space opens. Down/Up on the trigger opens at first/last enabled item; menu Up/Down/Home/End moves focus, character typing searches items. Escape closes and returns focus; outside click closes without stealing focus; Tab closes while preserving natural navigation. Item click emits `oj:select` with `{ item, value }`; `preventDefault()` keeps the menu open. Consumers manage checkbox/radio menu state and execute actions. `oj:open`/`oj:close`: `{ trigger, menu }`. For ordinary site navigation use native links, not menu roles.

## Tooltip

Set `data-oj-tooltip="Settings"` on an accessible trigger. `initTooltips` provides a plain-text `role="tooltip"` description on focus/hover, preserves existing `aria-describedby`, positions within the viewport and supports hover over the tooltip plus Escape dismissal. The tooltip is mounted in the owner document body (or its native dialog), hidden on dismissal and removed on cleanup. Essential instructions belong in visible text, never solely in a tooltip. Icon-only triggers still need `aria-label`.

`oj:open`/`oj:close` bubble from trigger with `{ trigger, tooltip }`.

## Native dialogs

Give `dialog.oj-dialog[data-oj-dialog]` a title via `aria-labelledby`. Declarative open buttons use `data-oj-dialog-open="id"`; close buttons inside use `data-oj-dialog-close` or a return-value string. Native `method="dialog"` forms work too.

```js
openDialog('settings', { root: document, trigger: settingsButton });
closeDialog('settings', 'saved');
const confirmed = await confirmDialog({
  title: 'Delete project?',
  message: 'This action cannot be undone.',
  confirmLabel: 'Delete',
  cancelLabel: 'Cancel',
  variant: 'danger',
});
```

The browser handles modal focus/inertness/Escape. Helpers preserve an opener and restore focus if it remains connected; autofocus is honored. `confirmDialog` inserts safe text, focuses Cancel, resolves false for cancellation/Escape, and removes temporary markup/listeners. `oj:open`/`oj:close` bubble from dialog: `{ dialog, returnValue }`. Do not nest native dialogs in other dialogs or provide an inert root.

## Toast

```js
const notification = toast('Export completed', {
  type: 'success',
  duration: 4000,
  root: document,
  dismissLabel: 'Dismiss notification',
});
notification.dismiss();
```

Types: info (default), success, warning, danger; error aliases danger. Duration is milliseconds; 0 persists until dismissed. Toasts stack in a local region, have live announcements and labeled dismiss controls, and pause timers while hovered/focused. Root defaults to the document; a theme-scoped element root preserves the local product identity. The region is removed after its final toast is dismissed. Avoid auto-dismissing essential information; use persistent alerts or duration 0 when user action is required.

Returns `{ element, dismiss }`. `oj:open`/`oj:close` bubble with `{ element, type }`. Message values are rendered with `textContent`; there is no HTML message mode, remote script loading or business state. Other helpers also treat text literally.
